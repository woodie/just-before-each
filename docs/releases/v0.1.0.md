# just-before-each v0.1.0

## Initial release

[Quick](https://github.com/Quick/Quick)'s `justBeforeEach` for
[Kotest](https://kotest.io)'s `DescribeSpec`. Kotest's own `beforeEach`
reruns fresh before every `it`, from the outermost `describe` inward, but
has no hook that runs *after* every `beforeEach` at every nesting depth,
immediately before the `it` itself. `justBeforeEach` separates what varies
(ordinary `beforeEach` in each `context`) from the action under test
(declared once, in the parent):

```kotlin
import com.netpress.justbeforeeach.justBeforeEach
import io.kotest.core.spec.style.DescribeSpec
import io.kotest.matchers.shouldBe

class CalculatorSpec : DescribeSpec({
    describe("#divide") {
        var numerator = 0
        var denominator = 1
        var result = 0
        justBeforeEach { result = Calculator.divide(numerator, denominator) }

        context("dividing evenly") {
            beforeEach { numerator = 10; denominator = 2 }
            it("returns the quotient") { result shouldBe 5 }
        }

        context("dividing with a remainder") {
            beforeEach { numerator = 7; denominator = 2 }
            it("truncates toward zero") { result shouldBe 3 }
        }
    }
})
```

## Setup required

`justBeforeEach` blocks are only *recorded* until `JustBeforeEachExtension`
is registered in the consuming project's `ProjectConfig` -- without it,
every `justBeforeEach` block is a silent no-op. See the README's "Setup".

## Design: `TestCaseExtension`, not a shadowed DSL

An earlier design shadowed `describe`/`context`/`it` with wrapped versions.
That doesn't actually work -- Kotest's DSL functions are default-implemented
interface members, and a nested `describe`/`context` block runs against a
Kotest-internal scope object with nothing of this library's in its type
hierarchy to override. What ships instead: `describe`/`context`/`it` stay
completely vanilla Kotest; only `justBeforeEach` (a new extension function)
and `JustBeforeEachExtension` (a real `TestCaseExtension`, Kotest's own
documented extension point) exist. See `docs/COWORK.md`'s "Core mechanism"
for the full story, including the real compile errors the first inspection-
only pass got wrong and how each was fixed against Kotest's actual source.

## The `runCatching`-outcome convention

Hoisting an action that might throw into `justBeforeEach` breaks naively --
the exception fires during setup, outside any `it`. Capture the outcome
with the stdlib's own `runCatching` instead, so a happy-path and an
error-path sibling `context` can share the same hoisted action. See the
README's own section for the worked example.

## Testing

Confirmed on real hardware, not just by inspection: this repo's own
`JustBeforeEachSpec.kt` (4 examples covering the ordering guarantee and the
`runCatching`-outcome convention), and end to end in
[`next-caltrain-kotlin`](https://github.com/woodie/next-caltrain-kotlin)'s
`GoodTimesSpec.kt` -- the `debugOverrideDotw` context this library was
built to clean up, 81 examples total, 0 failed. `make lint` clean in both
repos.

## Scope

Consumed by `next-caltrain-kotlin` via a Gradle composite build
(`includeBuild("../just-before-each")`), not a published artifact -- not on
Maven Central at this point. Both repos need to sit as sibling directories
on disk for `next-caltrain-kotlin`'s build to resolve this dependency.
