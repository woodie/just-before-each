# kwick v0.1.1

## Fix: container test cases were getting wrapped too

`JustBeforeEachExtension.intercept` fires for every `TestCase` Kotest
builds -- and Kotest represents every `describe`/`context` as a `TestCase`
too (`type = TestType.Container`), not just `it` (`type = TestType.Test`).
`intercept` never checked `testCase.type`, so it wrapped containers exactly
like leaves. A container's own `test` closure is the code that *discovers
its children*, which runs before any descendant `beforeEach` has assigned
anything -- so a hoisted `justBeforeEach` block ran during tree discovery
instead of before each real test, throwing
`kotlin.UninitializedPropertyAccessException` on any `lateinit var` it read
but hadn't been assigned yet.

This existed since `v0.1.0`. It never surfaced because every real usage up
to this point either read a plain `var` with a harmless default value, or
had its side effects cleared (by a `beforeEach` further up the chain)
before the real assertion ran. Caught for real once
[`next-caltrain-kotlin`](https://github.com/woodie/next-caltrain-kotlin)
expanded its own `justBeforeEach` usage to a case that reads a true
`lateinit var` -- reported as an `initializationError` on the container
itself, not on any single `it`, which is what gave the real cause away.

## The fix

`intercept` now skips anything that isn't `TestType.Test` -- container test
cases pass through completely untouched, only real leaf `it`s get their
`test` closure wrapped. No change to `justBeforeEach`'s own call signature
or any consumer-facing API.

## Testing

Added a regression case to this repo's own `JustBeforeEachSpec.kt`
("reading a lateinit var only set by a nested beforeEach") that reproduces
the exact shape -- throws without the fix, passes with it. Confirmed on
real hardware: `make check` here (5 examples, 0 failed), and
`next-caltrain-kotlin`'s own `make test` (81 examples, 0 failed) with the
new `.optionIndexFor()`/`.direction()`/`TripViewModel` `justBeforeEach`
usages that originally caught this.

## Scope

Same as `v0.1.0`: consumed by `next-caltrain-kotlin` via a Gradle composite
build (`includeBuild("../kwick")`), not a published artifact -- not on
Maven Central at this point.
